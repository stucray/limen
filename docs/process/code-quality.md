# Code-quality reports

This project uses [PMD](https://pmd.github.io/) to surface complexity hot-spots
in `src/main/java`. Findings here are non-gating — PMD's job is to inform
refactoring, not block builds. (Error Prone and NullAway _do_ gate the build;
they're configured in `pom.xml` under `maven-compiler-plugin`.)

## Where the reports live

- [`docs/reports/code-quality.md`](../reports/code-quality.md) — human digest
  with headlines, per-package + per-rule summaries, and top-10 hot-spots
  (with source links).
- [`docs/reports/code-quality.json`](../reports/code-quality.json) — flat
  findings array + summary header. Stable schema; sort key is
  `(rule, package, class, method, begin_line)` so unrelated edits that
  shift line numbers don't churn the diff.

Both files are committed and regenerated by `mvn verify`.

## Regeneration

```sh
mvn verify
```

Maven runs PMD (writes `target/pmd.xml`) and then invokes
`scripts/render-pmd-report.py`, which atomically rewrites both report files
in place (tmp + rename — never half-written).

To run the script directly (e.g. iterating on the script itself):

```sh
python3 scripts/render-pmd-report.py \
  --in target/pmd.xml \
  --out-md docs/reports/code-quality.md \
  --out-json docs/reports/code-quality.json
```

The script is stdlib-only Python — no `pip install` step.

## Ad-hoc PMD HTML drilldown

For interactive browsing of all findings (with cross-reference links into
source):

```sh
mvn pmd:pmd -Dformat=html
open target/pmd.html   # gitignored; regenerate any time
```

This is the escape hatch when the curated digest doesn't have what you need —
typically when chasing a specific rule violation in detail.

## Ruleset

Defined in [`pmd-ruleset.xml`](../../pmd-ruleset.xml). Currently complexity-only;
broadening (Best Practices, Performance, Error Prone PMD-rules) is tracked in
[#189](https://github.com/stucray/limen/issues/189) so each category's
contribution to `code-quality.json` is auditable in isolation.
